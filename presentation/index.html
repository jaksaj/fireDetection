PROJECT SCOPE & OBJECTIVE

Multi-Stage Smoke & Fire Edge Intelligence

This project showcases the systematic evolution of computer vision models developed for forest fire and smoke monitoring on power-constrained edge computing devices. The pipeline refines from a simple binary presence classifier to an advanced semantic segmentation model that extracts pixel-level hazard boundaries.

Task Granularity Progression: presence → class → robustness → location → pixel precision. Each stage balances the trade-offs between computational cost, edge latency, and spatial detail.

Dataset Refinement

Iterations 1 - 4 utilize the D-Fire Dataset split, which is built on YOLO bounding boxes and global class labels. This dataset maps fire and smoke scenarios, mixed cases, and neutral normal scenes.

Iteration 5 transitions to the Roboflow COCO Segmentation dataset (7,110 images, polygonal masks). This dataset shift was required to feed the U-Net model with dense pixel-level masks instead of coordinates.

Edge Optimization Pillars

  • Global Average Pooling: Replaces dense layers to minimize parameter counts.
  • Transfer Learning: Freezing backbones to lock visual features, unfreezing top layers for differential learning rates.
  • Post-Training Quantization (PTQ): Quantizing models from FP32 to INT8 to simulate edge latency gains.
  • End-to-End Box Regression: Utilizing YOLO26n for NMS-free inference.

Neural Network Architecture

Custom FireCNN: Scratch-built in PyTorch

Custom initialization utilizes Kaiming Normal for convolutional kernels and Xavier Uniform for the linear head. The global pooling layer makes this scratch model extremely lightweight (~389k parameters) and edge-friendly.

Advantages & Milestones

  • Minimal Footprint: Model file is just ~1.5 MiB, easily fitting in cache on low-cost CPUs.
  • Numerical Stability: Binary cross entropy configured with raw logits to prevent floating-point underflow.
  • Validated Pipeline: Verified correct data reading, model creation, checkpointing, and evaluation scripts.

Shortcomings & Challenges

  • Binary Limitation: Cannot separate smoke from fire. Smoke-only and mixed scenes are grouped into "fire presence".
  • Low Real-world Semantic Value: A forest monitoring engine needs to alert specifically if smoke exists without fire (early warning).
  • Edge Case Vulnerability: The baseline custom CNN is prone to false alarms on clouds, fog, and sun glare due to lack of deep semantic features.

Neural Network Architecture

MobileNetV3-Small: Two-Stage Training Setup

Training Strategy: Phase 1 freezes the backbone (only head parameters update). Phase 2 unfreezes the top 3 convolutional blocks of MobileNetV3-Small. Differential learning rates are used (1e-5 backbone, 1e-4 classifier) to prevent catastrophic forgetting.

Advantages & Milestones

  • Semantic Expansion: Supports separating smoke from fire, which is key for early alarms.
  • Deep Feature Learning: Pretrained weights allow mapping of subtle shapes, fog, and light reflection.
  • Compact Backbone: MobileNetV3-Small uses squeeze-and-excitation modules with hard-swish activations for low latency.

Shortcomings & Challenges

  • Class-wise Performance Gap: The "Only Fire" class scored a lower F1 score (68.78%) compared to "Neither" (94.83%).
  • Imbalance Instability: The dataset has much fewer fire-only samples. Standard loss, even weighted, struggles to align minority boundaries.
  • Real-world Brittle Boundaries: Struggles with environmental edge cases like smoke-colored morning mist, dust, or moving clouds.

Robust Training & Quantization Pipeline

Albumentations → Cosine Annealing → INT8 Quantization

The cosine annealing learning rate scheduler gradually drops the learning rate to zero following a cosine curve, allowing the model to settle in smooth local minima. This stabilizes weights, facilitating Post-Training Quantization (PTQ) to INT8 with minimal accuracy loss.

Advantages & Milestones

  • Generalization Gain: Test accuracy rose to 90.25%, and test F1 macro increased to 86.72%, indicating real robustness.
  • Memory Shrinkage: Model footprint dropped to 1.1 MiB, fitting easily in microcontroller SRAM or low-end CPU caches.
  • Edge Optimization Demo: Proved that applying INT8 quantization reduces power consumption and speeds up integer execution units.

Shortcomings & Challenges

  • Spatial Blindness: The model classifies the overall frame but does not reveal *where* the fire/smoke is.
  • Edge Box Boundary Lack: Does not calculate a bounding box or outline of the fire, making it hard to target suppression systems.
  • Loss of Localized Context: Dense global pooling throws away pixel spatial relations.

YOLO26n Single-Shot Object Detector

Anchor-Free, End-to-End NMS-Free Detection

YOLO26n leverages a decoupled architecture. Instead of evaluating candidate anchor templates, it estimates regression coordinates directly for each cell. This reduces computational latency, enabling fast GPU/NPU operations.

Advantages & Milestones

  • Localization Capability: Pinpoints bounding boxes around smoke plumes and fires, giving real coordinates.
  • NMS Bottleneck Cut: Direct end-to-end output eliminates classic Non-Maximum Suppression overhead.
  • Export Versatility: Direct conversion pathways to ONNX and TensorRT optimized for NVIDIA Jetson deployment.

Shortcomings & Challenges

  • Box Boundary Approximation: Square boxes capture a large amount of irrelevant empty space around amorphous, drifting smoke shapes.
  • High Computing Costs: Inputting 640x640 frames requires ~2.57M parameters, raising hardware requirements significantly.
  • Small Target Deficit: Struggles to identify far-away thin smoke trails where the box features disappear under downscaling.

U-Net Encoder-Decoder Architecture

Lightweight PyTorch implementation with Skip Connections

Skip Connections: Propagate fine-grained spatial features directly from the contracting path to the expanding path. This prevents fine detail loss that occurs during max-pooling, which is critical for mapping thin, wispy smoke trails.

Advantages & Milestones

  • High Spatial Precision: Generates exact mask contours, enabling spread analysis and flame perimeter sizing.
  • Class Balance Loss: Focal Loss focuses training on hard minority pixels, while Dice Loss optimizes structural overlap.
  • Mixed Precision (AMP): Using `torch.cuda.amp` reduces memory utilization, accelerating GPU training times.

Shortcomings & Challenges

  • High Compute Footprint: Custom U-Net with ~7.85M parameters is the heaviest model in the project.
  • Drastic Dataset Shift: Required custom mask preprocessing scripts to convert Roboflow polygonal coordinates to pixel masks.
  • Decoding Activation Latency: Bilinear upsampling and dense concatenations create high memory-bandwidth bottlenecks on edge CPUs.
